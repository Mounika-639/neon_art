What happens on screen

Five stages, played back to back — the live preview above highlights them as it runs

  1. The neon edge map is cut into a mosaic of 10 pixel blocks. Every block holding light becomes a dot, and the dots ignite in a seeded random order out of pure black — exactly the get_block_grid + shuffled reveal loop from the script.

  2. Block size collapses from 10 px to a single pixel on a (1 − t)² ease curve, so the coarse mosaic resolves into crisp line art. Nine mosaic levels are pre-computed as an image pyramid so every frame is a single scaled blit.

  3. Canny edges are tinted from the original colours (HSV saturation ×1.5, value ×1.25), then lit with a triple bloom — core, 4σ inner glow, 14σ outer glow — plus the mirrored floor glow from add_reflection.

  4. The glowing sketch dissolves and the real photograph rises through it — light giving way to form.

  5. The complete photograph is held on screen. In the default Fit framing the entire image stays visible on any display; the optional Fill modes crop instead so the picture reaches every edge.

What was ported, and what could not be

An honest account of the move from OpenCV / Python to the browser

✔ Genuinely re-implemented in JavaScript

These are real algorithms written out in script.js, not stand-ins:

  • cv2.Canny — Sobel gradients, non-maximum suppression, double threshold and stack-based hysteresis.
  • cv2.dilate with a 3×3 kernel, N iterations — exact (separable max filter).
  • The HSV saturation / value boost applied to edge pixels — exact.
  • get_block_grid’s block walk and DARK_PIXEL_SKIP — same 10 px grid, same skip threshold. (The colour each block takes was changed; see the middle column.)
  • The seeded shuffle, the dot reveal loop, the (1 − t)² refine curve, the crossfade, add_reflection and the AUTO_CONTRAST 99th-percentile normalisation.
  • load_and_fit’s cover crop — plus a new Fit mode that keeps the whole picture visible.

≈ Approximated — and here is the difference

  • cv2.bilateralFilter(gray, 7, 50, 50) is replaced by a 1.4σ Gaussian blur. A true edge-preserving bilateral filter is O(n·r²) per pixel and far too slow in JavaScript at full screen resolution. Edges in noisy or heavily textured areas therefore come out slightly differently from the Python run.
  • cv2.GaussianBlur(sigmaX=4 / 14) uses the browser’s own GPU Gaussian via ctx.filter = "blur()", with a three-pass box blur as a fallback on older Safari. Visually equivalent, not bit-identical.
  • Glow and mosaic constants were retuned. The original 1.4 / 1.1 / 0.7 × 1.6 gain saturated every edge to flat white on these images, and a 10 px brightest-pixel block lit up whole if a single pixel inside it was lit. The browser build uses softer gains and weights each block by how much of it is actually lit. This is a deliberate change, not a port error.
  • Two things here are additions, not ports. The Fit framing mode (the Python script only cover-crops) and the soft blurred backdrop that fills the letterbox behind a Fit-framed picture. The backdrop is decorative only — it is never fed to the edge detector, and the deity above it is drawn whole, uncropped and unstretched.

✕ Cannot be moved into a browser

  • cv2.imwrite / shutil.copyfile — a web page cannot silently write output_neon_sketch.png to your disk. The closest honest equivalent is the Save sketch button, which triggers a normal download you have to accept.
  • ctypes.windll.user32.GetSystemMetrics and the tkinter fallback — there is no API to read the physical monitor resolution. The page uses window.innerWidth/innerHeight and devicePixelRatio instead, which is the correct measure for a web canvas anyway.
  • cv2.namedWindow, WND_PROP_FULLSCREEN and cv2.waitKey — replaced by the Fullscreen API and DOM key events. On iPhone Safari the Fullscreen API does not exist at all, so the player falls back to a fixed full-viewport overlay.
  • Reading pixels from file:// — Chrome treats local files as opaque origins, so getImageData on an image loaded from images/ throws. Served over GitHub Pages (or any http/https host) this restriction disappears entirely.

i There was no AI or ML to port

The original script is classical image processing end to end — edge detection, blurs, colour-space maths and array reshaping. There is no neural network, no model file and no training step anywhere in it, which is precisely why it maps onto the Canvas 2D API so cleanly. Nothing has been faked or stubbed out to make the page look functional.

The only server-side pieces in the original were file I/O and the desktop window; both are listed above.
